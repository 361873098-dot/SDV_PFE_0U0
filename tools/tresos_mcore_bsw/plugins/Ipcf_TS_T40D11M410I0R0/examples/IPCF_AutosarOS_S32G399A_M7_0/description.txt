=====================================
IPCF Shared Memory sample application
=====================================

:Copyright: 2022-2023 NXP

Overview
========
This is the IPCF Shared Memory driver sample application for NXP S32 platforms
running on different core types. It demonstrates a ping-pong message communication
with another application core, using the shared memory driver.

Each application initializes the IPCF driver and waits for the other to initialize
as well (wait for remote core to be ready).

One application sends a message on an unmanaged channel with the number of messages
that will be sent (SENDING MESSAGES: 100) and starts sending (HELLO WORLD! from ...)
on a managed channel. Odd and even messages are sent on different channels.
The other application receives the messages and sends back the hello messages on
the channel with the same number (HELLO WORLD! from ...).
After receiving all expected messages, the application sends back the number of
received messages (REPLIED MESSAGES: 100) on the unmanaged channel.

HW Prerequisites
================
To run the example you will need to have the following items:
- 1 EVB board for supported processor (see Release Notes)
- 1 Power Adapter 12V (if the board cannot be powered from the USB port)
- 1 Personal Computer
- (Optional - In case of loading Cortex-M7 sample using s32xx.cmm) Lauterbach
debugger for supported platform

How to run
==========
1. Software installation::

  User must install correct version for software needed specified in
  IPCF Release Notes.

2. Example configuration::

  1. Make sure that IPCF plugin is already installed in the Tresos Studio
     plugins directory or linked
  2. Open Tresos Studio
  3. Import example application project:
      a. Click on "File" and select "Import"
      b. Select "Existing Projects into Workspace" and click on "Next" button
      c. Select "Select root directory" and click on "Browse"
      d. Select the location of the [project] folder in the installed example
         application package folder
      e. Click on "Finish" button

  The toolchain that will be used needs to be installed for correct operation
  and the path to the installation location shall be added into the system
  environment variable(s)::

    - TRESOS_DIR the installation path of Electrobit Tresos (used for generating
      the project from command line)

        Ex: TRESOS_DIR = C:/EB/tresos

    - GCC_DIR The path to the GCC instalation dir

        Ex: GCC_DIR = C:/NXP/S32DS.3.5/S32DS/build_tools/gcc_v9.2/gcc-9.2-arm32-eabi

    - GHS_DIR The path to the GHS instalation dir

        Ex: GHS_DIR = C:/ghs/comp_202114

    - DIAB_DIR The path to the DIAB instalation dir

        Ex: DIAB_DIR = C:/WindRiver/compilers/diab-7.0.4.0

    - IAR_DIR The path to the IAR instalation dir

        Ex: IAR_DIR = C:/IAR_8501/arm

    - PLUGINS_DIR The path to the Tresos plugins directory

        Ex: PLUGINS_DIR = C:/EB/tresos/plugins

    - SHM_DRIVER_PATH The path to the IPCF driver plugin directory

        Ex: SHM_DRIVER_PATH = C:/NXP/SW32G_IPCF_0.0.0_D0000/eclipse/plugins/Ipcf_TS_T40D00M00I0R0

  Open project_parameters.mk file in a text editor and update the variables
  mentioned above with the correct paths

3. Modifying the configuration in Tresos and generating the code::

  Users may change the application configuration according to their needs.

  1. Open the EB Tresos Studio GUI
  2. Open previously imported Example Application project
  3. Use the Tresos Studio GUI to modify configuration parameter values and
     save the changes.
  4. Select the Example Application project and click on "Generate" button to
     generate the configuration files.

4. Building the application::

  1. Open the Windows command prompt window
  2. Change the current directory to the example application folder
  3. To build the example, execute the following command to build:
     **make compiler=gcc build**
  4. The object files and linker output file (IPCF_AutosarOS_S32G399A_M7_0.elf)
     shall be generated in the /out subdirectory

  After build the file **IPCF_AutosarOS_S32G399A_M7_0.bin** also must be created.

5. Running the project::
  1. How to load the IPCF sample with s32xx.cmm::

      1. Open Lauterbach Trace application
      2. Load "s32xx.cmm" file form debug folder
      3. Set path to the IPCF_AutosarOS_S32G399A_M7_0 file
      4. Execute cmm script to load IPCF_AutosarOS_S32G399A_M7_0 file into the
      board
      5. After loading the IPCF sample establish the serial connection
      with S32G399A board and start booting the linux.

  2. How to load the IPCF sample from u-boot console::
      1. Copy the stripped binary (IPCF_AutosarOS_S32G399A_M7_0.bin) to a FAT
      partition on a SD-card
      2. Establish a serial connection with the S32G399A board and power it on
      3. Hit any key to stop in the u-boot console
      4. Disable Data Cache from uboot::

            dcache off

      5. Zero-set SRAM shared memory used by both sample apps::

            mw.q 0x34100000 0x0 0x40000

      6. Load binary in DDRAM and after is SRAM::

            fatload mmc 0:1 0x80000000 IPCF_AutosarOS_S32G399A_M7_0.bin
            cp.b 0x80000000 0x34300000 0x300000

      7. Start M7 core (the argument is the address of the Interrupt Vector)::

            startm7 0x34300000

      8. Boot Linux ::

            boot

      9. Login with root and run linux sample app::

            insmod /lib/modules/`uname -r`/extra/ipc-shm-dev.ko
            insmod /lib/modules/`uname -r`/extra/ipc-shm-sample.ko
            echo 10 > /sys/kernel/ipc-shm-sample/ping

      10. Result must appear like this::

            [ timestamp ] ipc-shm-sample: ipc-shm-sample: starting demo...
            [ timestamp ] ipc-shm-sample: ipc-shm-sample: ch 0 >> 20 bytes: SENDING MESSAGES: 10
            [ timestamp ] ipc-shm-sample: ch 1 >> 32 bytes: #0 HELLO WORLD! from KERNEL
            [ timestamp ] ipc-shm-sample: ch 1 << 32 bytes: #0 HELLO WORLD! from CORE 0
            [ timestamp ] ipc-shm-sample: ch 2 >> 32 bytes: #1 HELLO WORLD! from KERNEL
            [ timestamp ] ipc-shm-sample: ch 2 << 32 bytes: #1 HELLO WORLD! from CORE 0
            [ timestamp ] ipc-shm-sample: ch 1 >> 32 bytes: #2 HELLO WORLD! from KERNEL
            [ timestamp ] ipc-shm-sample: ch 1 << 32 bytes: #2 HELLO WORLD! from CORE 0
            [ timestamp ] ipc-shm-sample: ch 2 >> 32 bytes: #3 HELLO WORLD! from KERNEL
            [ timestamp ] ipc-shm-sample: ch 2 << 32 bytes: #3 HELLO WORLD! from CORE 0
            [ timestamp ] ipc-shm-sample: ch 1 >> 32 bytes: #4 HELLO WORLD! from KERNEL
            [ timestamp ] ipc-shm-sample: ch 1 << 32 bytes: #4 HELLO WORLD! from CORE 0
            [ timestamp ] ipc-shm-sample: ch 2 >> 32 bytes: #5 HELLO WORLD! from KERNEL
            [ timestamp ] ipc-shm-sample: ch 2 << 32 bytes: #5 HELLO WORLD! from CORE 0
            [ timestamp ] ipc-shm-sample: ch 1 >> 32 bytes: #6 HELLO WORLD! from KERNEL
            [ timestamp ] ipc-shm-sample: ch 1 << 32 bytes: #6 HELLO WORLD! from CORE 0
            [ timestamp ] ipc-shm-sample: ch 2 >> 32 bytes: #7 HELLO WORLD! from KERNEL
            [ timestamp ] ipc-shm-sample: ch 2 << 32 bytes: #7 HELLO WORLD! from CORE 0
            [ timestamp ] ipc-shm-sample: ch 1 >> 32 bytes: #8 HELLO WORLD! from KERNEL
            [ timestamp ] ipc-shm-sample: ch 1 << 32 bytes: #8 HELLO WORLD! from CORE 0
            [ timestamp ] ipc-shm-sample: ch 2 >> 32 bytes: #9 HELLO WORLD! from KERNEL
            [ timestamp ] ipc-shm-sample: ch 0 << 20 bytes: REPLIED MESSAGES: 10
            [ timestamp ] ipc-shm-sample: ch 2 << 32 bytes: #9 HELLO WORLD! from CORE 0
            [ timestamp ] ipc-shm-sample: exit demo

      11. Unload the modules::

            rmmod ipc_shm_sample ipc_shm_dev
