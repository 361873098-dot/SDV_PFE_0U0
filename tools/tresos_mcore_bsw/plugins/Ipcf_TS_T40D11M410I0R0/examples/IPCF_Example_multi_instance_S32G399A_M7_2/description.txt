=====================================================
IPCF Shared Memory Sample Multi-instances Application
=====================================================

:Copyright: 2022-2023 NXP

Application description
=======================
This is the IPCF Shared Memory driver sample application for NXP S32 RTD running
on Cortex-M7 core of NXP S32G platform. It demonstrates a ping-pong message
communication with a Linux kernel application, using the shared memory driver.
The application initializes the driver and does an echo reply for every message
received from Linux application.

HW Prerequisites
================
To run the example you will need to have the following items:
- 1 EVB board for supported processor (see Release Notes)
- 1 Power Adapter 12V (if the board cannot be powered from the USB port)
- 1 Personal Computer
- (Optional - In case of loading Cortex-M7 sample using s32xx.cmm) Lauterbach
debugger for supported platform

How to run
==========
1. Software installation::

  User must install correct version for software needed specified in
  IPCF Release Notes.

2. Example configuration::

  1. Make sure that IPCF plugin is already installed in the Tresos Studio
     plugins directory or linked
  2. Open Tresos Studio
  3. Import example application project:
      a. Click on "File" and select "Import"
      b. Select "Existing Projects into Workspace" and click on "Next" button
      c. Select "Select root directory" and click on "Browse"
      d. Select the location of the [project] folder in the installed example
         application package folder
      e. Click on "Finish" button

  The toolchain that will be used needs to be installed for correct operation
  and the path to the installation location shall be added into the system
  environment variable(s)::

    - TRESOS_DIR the installation path of Electrobit Tresos (used for generating
      the project from command line)

        Ex: TRESOS_DIR = C:/EB/tresos

    - GCC_DIR The path to the GCC instalation dir

        Ex: GCC_DIR = C:/NXP/S32DS.3.5/S32DS/build_tools/gcc_v9.2/gcc-9.2-arm32-eabi

    - GHS_DIR The path to the GHS instalation dir

        Ex: GHS_DIR = C:/ghs/comp_202114

    - DIAB_DIR The path to the DIAB instalation dir

        Ex: DIAB_DIR = C:/WindRiver/compilers/diab-7.0.4.0

    - IAR_DIR The path to the IAR instalation dir

        Ex: IAR_DIR = C:/IAR_8501/arm

    - PLUGINS_DIR The path to the Tresos plugins directory

        Ex: PLUGINS_DIR = C:/EB/tresos/plugins

    - SHM_DRIVER_PATH The path to the IPCF driver plugin directory

        Ex: SHM_DRIVER_PATH = C:/NXP/SW32G_IPCF_0.0.0_D0000/eclipse/plugins/Ipcf_TS_T40D00M00I0R0

  Open project_parameters.mk file in a text editor and update the variables
  mentioned above with the correct paths

3. Modifying the configuration in Tresos and generating the code::

  Users may change the application configuration according to their needs.

  1. Open the EB Tresos Studio GUI
  2. Open previously imported Example Application project
  3. Use the Tresos Studio GUI to modify configuration parameter values and
     save the changes.
  4. Select the Example Application project and click on "Generate" button to
     generate the configuration files.

4. Building the application::

  1. Open the Windows command prompt window
  2. Change the current directory to the example application folder
  3. To build the example, execute the following command to build:
     **make compiler=gcc build**
  4. The object files and linker output file (IPCF_Example_multi_instance_S32G399A_M7_2.elf,
     and IPCF_Example_multi_instance_S32G399A_M7_2.bin) shall be generated
     in the /out subdirectory

  Repeat those steps to build the sample on IPCF_Example_multi_instance_S32G399A_M7_1
  directory to get **IPCF_Example_multi_instance_S32G399A_M7_1.elf/.bin**, and on
  IPCF_Example_multi_instance_S32G399A_M7_0 directory to get
  **IPCF_Example_multi_instance_S32G399A_M7_0.elf/.bin** if they haven't been built.

5. Running the project::

  1. How to load the IPCF sample with s32xx_3_cores.cmm::

      1. Open Lauterbach Trace application
      2. Load "s32xx.cmm" file form debug folder
      3. Set path to the IPCF_Example_multi_instance_S32G399A_M7_0.elf
      IPCF_Example_multi_instance_S32G399A_M7_1.elf and
      IPCF_Example_multi_instance_S32G399A_M7_2.elf files
      4. Execute cmm script to load those files into the board
      5. After loading the IPCF sample establish the serial connection
      with S32G board and start booting the linux.

  2. How to load the IPCF sample from u-boot console::

      1. Copy the stripped binary (IPCF_Example_multi_instance_S32G399A_M7_0.bin,
      IPCF_Example_multi_instance_S32G399A_M7_1.bin,
      and IPCF_Example_multi_instance_S32G399A_M7_2.bin) to a FAT partition on a SD-card
      2. Establish a serial connection with the S32G board and power it on
      3. Hit any key to stop in the u-boot console
      4. Disable Data Cache from uboot::

            dcache off

      5. Zero-set SRAM shared memory used by both sample apps::

            mw.q 0x34000000 0x0 0x60000

      6. Load binary in DDRAM and after is SRAM::

            fatload mmc 0:1 0x80000000 IPCF_Example_multi_instance_S32G399A_M7_0.bin
            cp.b 0x80000000 0x34300000 0x180000
            fatload mmc 0:1 0x80000000 IPCF_Example_multi_instance_S32G399A_M7_1.bin
            cp.b 0x80000000 0x34480000 0x180000
            fatload mmc 0:1 0x80000000 IPCF_Example_multi_instance_S32G399A_M7_2.bin
            cp.b 0x80000000 0x34600000 0x180000

      7. Start M7 core (the argument is the address of the Interrupt Vector)::

            startm7 0x34400400

      8. Boot Linux ::

            boot
